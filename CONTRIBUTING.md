# Contributing

Thank you for helping improve this skill library. The goal is a clear, traceable and practical collection.

## Add a skill

- Give each skill one clear job and a descriptive, stable directory name.
- Include a concise `SKILL.md` with purpose, triggers, workflow, prerequisites, boundaries and expected output.
- Add supporting references, scripts, examples or evals when the workflow depends on them.
- State the license and compatibility accurately; do not guess or copy a license from another project.
- Include source attribution and preserve upstream notices when importing existing work.
- Avoid hard-coded secrets, personal data and unreviewed executable downloads.

## Improve documentation

Keep the README concise and task-oriented. Update `docs/SKILL_CATALOG.md` and `manifest.json` when adding or removing skills. Check all relative links and ensure that the description matches the actual contents.

## Safety expectations

Skills that publish, send, schedule, delete or modify external accounts must require explicit human approval before taking the action. Do not add fabricated statistics, unsupported claims or promises of guaranteed reach.

## Pull requests

Describe the problem, summarize the change, list relevant skill paths, identify any new dependencies and document the checks you performed.
